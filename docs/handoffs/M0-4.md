## Decisions made
- **Infrastructure ports are bound to `127.0.0.1`.** Developer tools on this machine can still reach them, but other machines on the network can't. Alternative: no host ports at all. Rejected because local `dotnet run`, psql and the RabbitMQ UI need them.
- **Redis has no password.** It is bound to localhost and holds only processed event IDs. Alternative: `requirepass` from `.env`. Easy to add later if M6-4 exposes the host.
- **Named volumes**, so data survives `docker compose down`. Reset with `down -v`. A fresh run for M5-2 needs `down -v` first. The passwords for SQL Server and PostgreSQL only take effect when a volume is first created; `.env.example` says so.
- **Images pinned to minor versions**, except SQL Server, which stays on `2022-latest`. Microsoft publishes patch updates for 2022 under that tag, and the existing setup already used it.
- **The API waits only for `db`.** It doesn't use the broker or Redis yet. M1-2 will add `rabbitmq` to its `depends_on`.

## Review this hardest
- **The API's connection string in `docker-compose.yml`.** Compose fills in the password, so a password containing `;` would break it. `.env.example` warns about this, and the generator I used produces only letters, digits and a leading `Sd1!`.
- **`ASPNETCORE_ENVIRONMENT: Development` stays**, so the demo accounts get seeded. That's intended for the local demo, and there's a comment flagging it for M6-4.
