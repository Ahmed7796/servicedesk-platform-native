## What changed
- `notification-service/pom.xml`, Maven wrapper (`mvnw`, `.mvn/`): Spring Boot 4.1.2, Java 21, jar named `app.jar`.
- `security/JwtConfig`: HS256-only decoder; key is base64-decoded to raw bytes; validators for lifetime, issuer `ServiceDesk` and audience `ServiceDesk.Api`.
- `security/RoleClaimConverter`: plain `role` claim to `ROLE_<role>` for the four known roles; unknown or missing grants nothing. `sub` is used as a plain string (never parsed as a UUID).
- `security/SecurityConfig`: `/actuator/**` denyAll; stateless, no CSRF, `/notify/health` open, everything else authenticated, method security enabled (so later tasks can use `@PreAuthorize("!hasRole('TriageService')")`).

- `db/migration/V1__baseline.sql`: empty baseline (`SELECT 1`). No tables.
- `Dockerfile` (multi-stage, JDK build, JRE runtime with `curl`, non-root user, HEALTHCHECK), `.dockerignore`, `.gitignore`.

## Review fixes (round 1)
- Actuator was reachable with any valid token; `/actuator/**` is now `denyAll` and a test proves 403 for Admin and TriageService on `/actuator` and `/actuator/health`. The yml comment is corrected.
- A key shorter than 32 bytes after base64 decoding now stops startup with an `IllegalStateException` naming `JWT_SECRET_KEY` (the key is not printed); tested with a 16-byte key.
- A token with no `exp` is rejected by a new validator; tested.
- Removed the duplicate `JwtTimestampValidator`; `createDefaultWithIssuer` supplies the lifetime check with the default 60 s clock skew.
- Added `JwtDecoderTest` cases: HS512-signed token rejected, `alg=none` token rejected.

## Decisions made
- Health is a small controller, not Actuator's endpoint, because Actuator's root health response also contains a `groups` key, which the contract's `Health` schema does not allow. The controller reuses Actuator's aggregated `HealthEndpoint` status (so the DB check counts) and `/actuator/**` is denied for everyone in `SecurityConfig` (Actuator's default `health` web exposure is still on; it cannot be switched off without removing the `HealthEndpoint` bean the controller uses). Alternative considered: Actuator with `additionalPath`/group tweaks; more config than code.
- Tests run without a database: `application-test.yml` excludes DataSource, JDBC, Flyway and the DB health contributor. The baseline migration is therefore NOT exercised by any test (Testcontainers deferred to M2-2 by decision). Honest note: no test in this task runs the datasource or Flyway configuration at all; that stays true until Testcontainers arrives in M2-2. Alternative: H2, rejected as it hides PostgreSQL differences.
- Boot 4 specifics found: `spring-boot-starter-webmvc`, `spring-boot-starter-flyway`, `spring-boot-starter-webmvc-test` (for `@AutoConfigureMockMvc`, package `org.springframework.boot.webmvc.test.autoconfigure`), `spring-boot-starter-security-test`; health classes live in `org.springframework.boot.health.*`.
- `JWT_SECRET_KEY` and `POSTGRES_PASSWORD` have no default, so the service refuses to start without them.
