## Decisions made
- **OpenAPI 3.1, with enums as `$ref`s into `events/defs.schema.json`**, so the event and HTTP contracts share one definition. Alternative: copy the enums into each file. Rejected because the copies would drift.
- **The contract describes the running API, not its generated `/openapi/v1.json`.** The generated document types enums as integers and gives submit's status as 200. Both are wrong, and the README says so.
- **The overdue badge is joined on the phone.** `GET /notify/overdue` is matched to `pending-for-me` by `requestId`, because the C# API has no way of knowing due times.
- **A 401 for a missing or invalid token has an empty body, and so does a 403 from a role check.** Login's 401 for wrong credentials is ProblemDetails. All are documented as they really behave rather than changed: changing them would be API work outside M0-3.
- **`pending-for-me` and detail return `requesterName`**, and audit entries include `actorName`, so the phone doesn't show raw UUIDs.
- **Triage posting writes no audit entry and publishes no event.** It is advisory and changes no state (rule 3 applies only to state changes).
- **`TriageService` gets 403 on `pending-for-me` and on submit.** It may only read and post triage.
