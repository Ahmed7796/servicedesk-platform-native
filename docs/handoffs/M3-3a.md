## Flow
1. No key: `skipped`, no LLM call, no HTTP. A non-UUID request id: `failed`, no calls.
2. Up to 4 rounds of `llm.step` with `TOOL_SPECS`. Each requested call (at most 4 per round) goes through `TriageTools.call`; its result is wrapped as data and returned to the model. A reply with no calls ends the rounds early.
3. One `llm.final(system, history, schema)` call with no tools; JSON text validated by `TriageSuggestionInput`; then our code calls `post_triage`. All of it runs inside `asyncio.timeout(60)`, each LLM call also in `wait_for(20)`.
4. Failure outcomes (nothing posted, one warning logged with request id and reason only): invalid output (names known fields and error types only), model/SDK exception (class name only), 403/401/400/404 from the API (not retryable), API unavailable and overall timeout (`retryable=True`, for M3-3c's retry).

## Decisions made
- The model never gets a way to write: only the two read tools are declared; unknown names and non-dict args come back as `invalid_arguments`; the final call has no tools; the post is our code after validation.
- Request text is only ever in tool results, inside one data block; the user turn holds only the request id.
- `TriageSuggestionInput` is strict while response models are lenient: it is what we send, and the API rejects extras anyway.
- No retry on valid-but-odd output (M3-5 owns fallback).
- One broad `except Exception` in `triage()`: the copilot is advisory, so a model or SDK bug must not crash the consumer; it logs the exception class only (a message could contain a key).

## Review this hardest
- Prompt injection stays the main risk: the wording of `SYSTEM` in `prompt.py` and the single data-block rule. The test proves the dispatcher and the call list, not that a real model obeys the instruction.
- `agent.py`: the broad `except Exception`, and that `reason` strings never include input text.
- `wrap_data` only collapses angle-bracket runs; other framing of data is not escaped (JSON escaping covers quotes).
- The final-call JSON schema is pydantic's, with `additionalProperties:false`; Gemini may reject some keywords (M3-3b adapter issue, not tested here).
