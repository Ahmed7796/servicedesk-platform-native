## Review steps for Ahmed
1. Read the format below, then open `triage-copilot/evals/review.csv` in a spreadsheet (UTF-8; if it shows odd characters, import as UTF-8).
2. For every one of the 50 rows fill `category` and `priority`, even where you agree with `proposed_category` / `proposed_priority`. The `reason` column says what cue I used. Use `note` for doubts. Check the `kind` too: "mislabelled" rows should have a `submitted_type` that is wrong for the real need.
3. Do not rename columns or change `id`. Save as CSV, UTF-8, same file name.
4. From `triage-copilot/`: `python -m evals.finalize --reviewer "Ahmed"` (or in Docker from the repo root: `docker run --rm -v "$PWD":/repo -w /repo/triage-copilot python:3.12-slim sh -c "pip install -q -r requirements-dev.txt && python -m evals.finalize --reviewer Ahmed"`). It stops with `REFUSED: ...` naming the row if any label is blank or unknown (matching is case-insensitive, so spreadsheet autocorrect is fine), and it will not overwrite an existing `cases.jsonl`.
5. Open `cases.jsonl` once: first line is the `_meta` header (`checked_by`, `checked_at`, `case_count`, `source_sha256` of the CSV), then 50 cases with `category` / `priority` and no `proposed_*`.
6. Only then can the lead run `python -m evals.run` (M3-4b). I never read, write or fix labels in `cases.jsonl`.

**The gate guards against honest mistakes, not tampering.** It refuses a missing file, a file with no `_meta` header or an empty `checked_by`, a wrong `case_count`, duplicate ids, labels outside the enums, and rows that still carry `proposed_*` fields. Anyone can type a name into the header or edit the file; `source_sha256` only links it to the CSV it came from. The draft file is refused by the same loader (it has no header).
