## Decisions made
- Closed contract enums (type, status, step decision, scope, audit action, priority) are `Literal`, so drift fails with `bad_response`. `position`, `escalatedFrom`, `suggestedRoute` are `str` (open labels). Alternative: Literal everywhere, rejected because a new position would crash the copilot.
- Ids are validated as UUIDs before any HTTP call, so no path injection and no wasted request.
- Audit trail and steps are sorted defensively (stable sort) although the contract says oldest first.
- `ServiceAuthError` (401 after the one retry) is mapped to `auth_failed` with a fixed message; client id is not repeated in tool results.
- Unrelated detail: I wrote the implementation before the tests in this session, then ran the tests; they passed first time. Treat the tests as written against the contract, not tuned to the code, but look at them with that in mind.

## Review this hardest
- Prompt injection: `description`, `title`, step `comment` and audit `details` are untrusted requester text. M3-3 must pass them to the LLM as data, not instructions (delimit them, never let them change tool use or the output schema), and must still validate the model output against the schema before posting.
- `_parse` in `servicedesk_client.py`: error messages are built from `loc` and error `type` only; check that no `input` value can reach a message.
- Unrecognised exceptions in the tool are re-raised, not swallowed.
