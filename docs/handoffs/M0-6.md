## Java to C# notes (C# tasks only)
- Npgsql is the ADO.NET driver (like the PostgreSQL JDBC driver); `Npgsql.EntityFrameworkCore.PostgreSQL` is the EF Core provider on top of it (like Hibernate's PostgreSQL dialect). In Java the driver and dialect are two separate jars; here the provider package pulls the driver in.
- `UseNpgsql(connectionString)` is like setting `spring.datasource.url` plus the Hibernate dialect, but in code. The connection string is `Host=...;Database=...;Username=...;Password=...` (key/value, not a `jdbc:` URL).
- `uint RowVersion` with `IsRowVersion()` is like JPA `@Version`, with a difference that matters: Hibernate increments the version column itself, while here PostgreSQL's own `xmin` (the id of the last transaction that changed the row) is the token, so there is no column of ours and no increment code. EF adds `WHERE xmin = @old` to the UPDATE; zero rows changed throws `DbUpdateConcurrencyException`, like `OptimisticLockException`.
- `DateTimeOffset` maps to `timestamptz`, like `OffsetDateTime`, but the Npgsql driver only accepts offset 0 on write, so we always store UTC.
- `HasFilter("\"SentAt\" IS NULL")` is a partial index; raw SQL goes through as written, so PostgreSQL needs quoted identifiers because EF created the columns with capital letters. JPA has no annotation for partial indexes.
- Regenerating one migration instead of editing old ones is like replacing a Flyway baseline when nothing is deployed; EF migrations are generated C# classes plus a model snapshot, not hand-written SQL files.
