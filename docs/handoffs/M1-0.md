## Decisions made
- Resolver is an Application class, not on the repository, because it holds domain filtering and needs to be testable with a mock repository. Alternative: put it on the repository (would need a DB to test).
- Status is part of eligibility: no pending step or a non-decidable status (Approved, Rejected, Cancelled, Fulfilled) gives an empty list, no exception.
- The predicate uses the `ApproveStep` trigger for the state check. Reject allows the same statuses, and the exhaustive test checks Approve and Reject both agree.
- An Admin requester is excluded by the requester rule. Their `RequesterPosition` is null (only approvers get a snapshot), so the Admin fallback never applies to them. A dedicated test proves it.
- Result is sorted by ID so event payloads are deterministic.

## Java to C# notes (C# tasks only)
- Primary constructor `ApproverResolver(IUserRepository users)` is like a Spring constructor-injected `final` field with Lombok `@RequiredArgsConstructor`; the parameter is captured and usable in methods, with no field declaration.
- `AddScoped<ApproverResolver>()` is like a `@Service` bean with request scope; there is no annotation, registration is explicit in `AddApplication`.
- `Task<IReadOnlyList<Guid>>` with `async`/`await` is like `CompletableFuture<List<UUID>>`, but `await` unwraps it without blocking a thread. `IReadOnlyList<T>` is a read-only interface, like returning `Collections.unmodifiableList(...)` (a read-only view, not a copy): the `List<T>` behind it can still be changed by whoever holds it. It is not like `List.copyOf(...)`, which makes an immutable copy.
- `candidates.Where(...).Select(...).Order().ToList()` is like a Java Stream (`filter`/`map`/`sorted`/`toList`); LINQ on in-memory lists runs immediately at `ToList()`, and `request.CanDecideCurrentStep` is passed as a method group, like `request::canDecideCurrentStep`.
- `private enum DecisionBlock` nested in the class and a `switch` expression with `throw` arms is like a Java 21 switch expression over an enum; `out var step` returns a second value, which Java does not have (you would return a record).
- `step!` is the null-forgiving operator: it tells the compiler "not null here" and generates no check, unlike `Objects.requireNonNull`.
- `[]` is a collection expression (empty list), like `List.of()`.
- In EF Core, `db.Users.Where(...).ToListAsync()` is translated to SQL, like a Spring Data derived query, but written as a lambda instead of a method name.
