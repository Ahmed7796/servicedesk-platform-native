## How the runner works
1. Builds `Settings` from the environment (`GEMINI_API_KEY`, `GEMINI_MODEL`; the ServiceDesk values are unused placeholders) and `build_llm`. No key: prints `Set GEMINI_API_KEY first.` and exits 2, before reading any cases.
2. `--limit` below 1 exits 2. `--out` outside `evals/results/`, a directory, or an existing file without `--force` exits 2. All of these are checked before any model call. The check-then-write is not atomic (a file created between the check and the write is overwritten); fine for a local tool.
3. `load_checked("cases.jsonl")`; a `CasesError` prints `REFUSED: <message>` and exits 2.
4. Per case, with a semaphore (default 2) and a pause (default 1 s) that runs inside the concurrency slot, so it applies per slot and is not a global pace: the real `triage()` with `TriageTools` over the stub. A `posted` outcome yields the captured suggestion. A retryable outcome (`LlmRetryableError`, timeouts, API unavailable) is retried at case level: 3 attempts, waits of 2 s then 6 s. The retry count is the total of re-attempts across cases and is printed separately. A non-retryable failure (invalid output, 4xx) is not retried. A case still failing is a `Result` with no suggestion: counted as failed, never as wrong.
5. Prints the model id and `score.py`'s report (both accuracy figures labelled, confusion matrices, injection subset with category/priority/both, echo count, failure reasons, retries). `--out` writes ids, kinds, labels, suggestions and failure reasons, no request text.

## Assumptions (free tier)
About 10 to 15 requests a minute; each case makes 2 to 4 model calls (one `step` per tool round plus `final`); 50 cases is roughly 150 calls, so a run takes several minutes. Defaults are 2 at a time and a 1 s pause. If 429s appear in the retries line, lower `--concurrency` or raise `--pause`. Not measured against the live API.

## Live smoke (lead, scratch copy outside the repo, 2-case file marked as a smoke test)
Both cases ended as failed with reason "llm unavailable" after 3 attempts, with 4 retries reported separately; the results file had no request text; exit code 0. The cause was on Gemini's side: 503 on gemini-3.5-flash-lite and 504 on gemini-3.1-flash-lite at the time. So the retry, failed-not-wrong and reporting paths are confirmed against the real adapter, but the **pace defaults (concurrency 2, 1 s per-slot pause, 2 s and 6 s backoff) are untested against a healthy Gemini**; the first full run may need `--concurrency 1` or a longer `--pause`.
