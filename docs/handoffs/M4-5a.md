## Decisions made
- No token cache, because the endpoint is idempotent and a different user signing in on the same phone must re-link the token.
- Sign-out does not unregister: the contract has no unregister endpoint. Known limit: between sign-out and the next login on that phone, pushes for the old user can still arrive there. When someone else logs in, M2-4a moves the token to them.
- No `expo-device`: on an emulator that cannot issue a token, the failure is silent.
- Platform comes from `Platform.OS` only; web is skipped.

## Review this hardest
- `registerForPush`: that nothing can reject or show UI, and that `status` handling matches Expo's `granted` string.
- The Login hook placement: it runs after `tokenStore.set` and before `replace`. If `tokenStore.set` throws, it is not reached (correct: no token, no registration).
- The projectId check runs before any permission prompt, so a build without a `projectId` never prompts the user.
- Whole-app effect of `jest.setup.ts`: any future suite gets denied permission by default.
