## Decisions made
- Tombstone (`closed = true`) instead of delete, so a late older `submitted` cannot resurrect a finished request. Alternative: hard delete.
- Every write is guarded by `last_event_at < :occurredAt` (strict). Replays and older events are no-ops. `step_approved` also requires `closed = false`.
- `position varchar(30)` matches the contract's `maxLength`.
- UUID array bound as a `{a,b}` string with `CAST(... AS uuid[])` so it does not depend on driver array support.
- The `test` profile gets a mock `JdbcClient` rather than excluding the new beans; the DB tests use a separate `dbtest` profile.

## Review this hardest
- The SQL guards in `PendingStepRepository` (strict `<`, tombstone, `closed = false` on `moveToStep`).
- Known limits, not fixed: a `step_approved` or terminal event that arrives before its `submitted` has no row to act on (warn and ack), so a later `submitted` creates a stale step 1 for a request that has moved on. Fixing it needs `title` nullable or a placeholder row; I did not do that.
- A terminal event that arrives before its `submitted` leaves a later `submitted` creating an open row for a finished request. The lead accepts this for the demo: the outbox publishes in order and only retries reorder.
- Equal `occurredAt` on two different events for one request: the second is ignored by the strict guard. The API orders by `occurredAt` then `eventId`, so this should not occur in practice.
