## Tool: get_requester_history
- Args: `requester_id` (uuid, required), `exclude_request_id` (uuid), `limit` (integer 1 to 10, default 5; bool, string and float are rejected).
- Result: `{requester_id, total_matching, returned, requests:[{id, title, type, status, created_at, steps_summary}]}`; `steps_summary` is e.g. `HrManager:Approved,Newcomer:Pending`. Filtered by `requesterId` on the client, `exclude_request_id` removed, newest first (ties broken by id), then capped. `total_matching` is the count before the cap.
- Dispatcher: non-dict args, an unknown tool name and unknown args all return `invalid_arguments` and make no HTTP call. Unexpected exceptions (not our API errors) are raised, not returned.

## Decisions made
- Leakage test covers both tools across 401 twice, token endpoint 401, 403, 503 and a malformed 200; it checks the secret, `tok-` and a payload sentinel are absent from the result.
- Spec for `limit` carries `minimum`, `maximum` and `default`; the code enforces the same bounds.
- Ids are compared in lower case: the input is normalised by `UUID(...)` and the API ids are lower-cased for the comparison.
