## Decisions made
- Default + fallback policy instead of class-level `[Authorize]`, because ASP.NET Core ANDs `[Authorize]` attributes, so a method-level attribute cannot widen a class-level one. An endpoint with no attribute, or a bare `[Authorize]`, is humans only; only an explicit `Policy = ...` lets `TriageService` in. Alternative: list every human role on every action (easy to forget on a new one).
- Both id and secret are compared (hash first, so lengths are equal, single `&`, no short-circuit). An unknown id and a wrong secret return the same 401 body as login.
- Request DTO uses `[JsonUnmappedMemberHandling(Disallow)]` so an extra property is a 400, matching `additionalProperties: false`.
- `GetCurrentUserId` is unchanged except its comment: it is no longer what stops a service token.

## Review this hardest
- The structure in `ApiServiceCollectionExtensions` and `ServiceRequestsController`: the missing class-level attribute is deliberate (see comment). The reflection test `Actions_AreProtected_...` fails if someone adds a bare `[Authorize]` at class level.
- `ServiceClientOptions.Matches`: the constant-time claim cannot be tested.
- `ServiceTokenApiFactory` uses `UseSetting` (not `ConfigureAppConfiguration`) because `Program.cs` reads configuration while registering services.

## Java to C# notes (C# tasks only)
- Authorization policy (`AddAuthorization(options => ...)`) is like a Spring Security `authorizeHttpRequests` rule set or a custom `AuthorizationManager`. `[Authorize(Roles = ...)]` is `@PreAuthorize("hasAnyRole(...)")`, with no `ROLE_` prefix. A named policy is closest to a reusable `@PreAuthorize("@bean.check()")` expression.
- Default and fallback policy: the fallback is like `.anyRequest().authenticated()` at the end of the filter chain (endpoints with no attribute); the default policy is what a bare `@PreAuthorize("isAuthenticated()")` equivalent (`[Authorize]`) means. In Spring, a method-level `@PreAuthorize` replaces the class-level one, so a method can widen access. In ASP.NET Core, `[Authorize]` attributes are ANDed: a class-level one still applies to every method, so a method-level attribute can only narrow access, never widen it. That is why the class-level `[Authorize]` had to be removed.
- `CryptographicOperations.FixedTimeEquals` is like `MessageDigest.isEqual`. The difference that matters: it returns early when lengths differ, so I hash both sides first and compare the equal-length digests.
- `const string Human = $"{nameof(...)},..."` is a compile-time constant, like a Java `static final String`; attributes need constants, and `nameof` keeps it tied to the enum.
- `sealed record ServiceClientOptions(...)` is like a Java `record`; I used it as an immutable config holder instead of `@ConfigurationProperties`.
- `WebApplicationFactory<Program>` is like `@SpringBootTest` with `MockMvc` / `WebTestClient`; `public partial class Program;` exposes the top-level-statements entry point the way a public `@SpringBootApplication` class would be visible. `ConfigureTestServices` plays the role of `@MockBean`.
- `IClassFixture<T>` is xUnit's way to share one expensive object (the factory) across tests in a class, like a `@BeforeAll` shared context.
- `[JsonUnmappedMemberHandling(Disallow)]` is like Jackson's `FAIL_ON_UNKNOWN_PROPERTIES` for one type.
