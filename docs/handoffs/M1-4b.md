# Hand-off: M1-4b Triage suggestion endpoint

**Agent:** api-dotnet  **Date:** 2026-11-18

## What changed
- `POST /api/service-requests/{id}/triage` (`ServiceRequestsController`): `TriageService` only, through the new `CanPostTriage` policy.
- `TriageSuggestionService` (new): validates, checks the request exists, upserts. Its only dependencies are `IServiceRequestRepository`, `ITriageRepository` and `TimeProvider`: no unit of work, outbox or audit log.
- New table `TriageSuggestions` (entity, EF configuration, migration `AddTriageSuggestions`). PK = FK = `RequestId`, cascade on delete. The `ServiceRequests` row (and its `xmin`) is never touched.
- `TriageRepository`: one `INSERT ... ON CONFLICT ("RequestId") DO UPDATE` statement via `ExecuteSqlInterpolatedAsync`.
- `GET {id}` now returns `ServiceRequestDetailDto` (request fields plus `triage`); `pending-for-me` returns the real `TriageSuggestionDto?` in `PendingItemDto.Triage` (was `object?`). Pending loads all suggestions in one query.
- `GET /api/service-requests` (list) is unchanged: the contract `ServiceRequest` schema has no `triage`.
- `IServiceRequestRepository.ExistsAsync` (new).
- API-wide change: `JsonStringEnumConverter(allowIntegerValues: false)`. Every endpoint now rejects integer enums (400), matching the contract's string enums. No existing test or client sent integers.
- `TriagePriority` enum in `Domain/Enums` (not in `defs.schema.json`).
- Existing test files edited (fixture only, no assertion changed): `ServiceRequestServiceTests.cs`, `ServiceRequestServiceOutboxTests.cs`, `PendingForMeTests.cs` (extra constructor argument `Substitute.For<ITriageRepository>()`); `ServiceTokenApiFactory.cs` (an `ITriageRepository` substitute); `ServiceTokenEndpointTests.cs` (one added assertion that `PostTriage` names `CanPostTriage`).

## Known limits
- ASP.NET's web JSON defaults accept numbers sent as strings (`"confidence":"0.8"`), which is lenient against the contract's `number`. This is pre-existing and API-wide.

## Decisions made
- Own table, so `xmin` of the request never changes and an approver acting at the same time gets no spurious 409. Alternative: owned columns on `ServiceRequests`.
- Raw SQL upsert because it is one atomic statement: two concurrent first posts cannot both fail on a duplicate key. Alternative: EF update-then-insert with catch-and-retry.
- `suggestedRoute` as `text[]` of position names, matching the string enums elsewhere. Alternative: jsonb.
- Summary is trimmed, then checked for 1 to 500 characters, and stored trimmed.
- DTO members are nullable so a missing `confidence` is `null` and rejected (never 0). Validation lives in the service and throws `ArgumentException`, which `DomainExceptionHandler` already maps to 400. Unknown JSON properties are refused by `[JsonUnmappedMemberHandling(Disallow)]`.
- Validation runs before the existence check, so an invalid body for an unknown id gets 400, not 404.
- Triage is allowed in any request status; the contract does not restrict it.

## Review this hardest
- `TriageRepository.UpsertAsync`: raw SQL with quoted identifiers; a typo would only show against a real database.
- The `PrimitiveCollection(...).ElementType().HasConversion<string>()` mapping in `TriageSuggestionConfiguration` and the generated migration.
- The global enum converter change (`allowIntegerValues: false`).
- Known limit: if the request were deleted between the existence check and the upsert, the foreign key fails and the caller gets a 500. Requests are never deleted today.

## Java to C# notes
- `record` DTOs (`TriageSuggestionInputDto`, `TriageSuggestionDto`) are like Java records or a Lombok `@Value` class; the difference is that `with` copies a record with some fields changed (used in tests) and the positional constructor is also the JSON binding shape.
- `RequestType?` (nullable enum) is like a boxed `Integer`/nullable field in Java; the difference is that it is a language feature on value types, so "missing" (`null`) is distinct from the enum's first value (0).
- `[JsonUnmappedMemberHandling(Disallow)]` is like Jackson's `FAIL_ON_UNKNOWN_PROPERTIES` on one class; the difference is it is an attribute on the type, not a global mapper setting.
- `[Authorize(Policy = ...)]` plus `AddPolicy` is like `@PreAuthorize("hasRole('TRIAGE_SERVICE')")` or a Spring Security `SecurityFilterChain` rule; the difference is that the policy is registered by name and the attribute only refers to the name.
- `ExecuteSqlInterpolatedAsync($"...{value}...")` looks like string concatenation but is like `JdbcTemplate.update(sql, args)` with `?` placeholders: the compiler passes a `FormattableString`, and EF turns each `{value}` into a SQL parameter.
- `INSERT ... ON CONFLICT DO UPDATE` is PostgreSQL's upsert; in Spring Data JPA `save()` would do select-then-insert/update in two steps, which can race.
- `IUnitOfWork` is like Spring's `@Transactional` boundary; not injecting it into `TriageSuggestionService` is how the service is kept from writing through EF's change tracker.
- Primary constructors (`class TriageSuggestionService(IServiceRequestRepository requests, ...)`) are like Lombok `@RequiredArgsConstructor` with the fields declared on the class; the parameters are captured and usable in every method.
- `AsNoTracking()` is like a read-only transaction or a detached entity in JPA: EF does not keep the object in its change tracker, so nothing is written back.
- Pattern `input.Confidence is not { } confidence` means "null check, and bind the non-null value to `confidence`" (like `if (x == null) throw ...; double c = x;`).
