# Hand-off: M2-3 due times and GET /notify/overdue

**Agent:** notify-spring  **Date:** 2026-11-18

## What changed
- `overdue/StepSlaProperties`: `app.notify.step-sla` (env `NOTIFY_STEP_SLA`, strict ISO-8601, default `PT24H` when unset). Bound as a `String` and parsed with `Duration.parse` in the record constructor, because Spring's own Duration converter accepts a simple format (`24` binds as 24 ms, `24h` as PT24H). Zero, negative, empty or non-ISO values (`24`, `24h`, `abc`, `PT24`) stop startup with a message naming `NOTIFY_STEP_SLA` and the example `PT24H`. `duration()` returns the parsed value.
- `overdue/ClockConfig`: a `Clock.systemUTC()` bean; tests replace it.
- `overdue/OverdueRepository`: one query on `pending_step`: open rows with `pending_since < cutoff`, optionally `assignee = ANY(assigned_user_ids)`, ordered by `pending_since`. Maps to `OverdueStepDto`, adding the SLA for `dueAt`.
- `overdue/OverdueService`: scope by role. `overdue/OverdueController`: `GET /notify/overdue`, `@PreAuthorize("!hasRole('TriageService')")`. `overdue/OverdueStepDto`: the contract's 8 fields.
- `application.yml`: one new setting (`app.notify.step-sla: ${NOTIFY_STEP_SLA:PT24H}`). `src/test/resources/application-dbtest.yml`: `app.notify.step-sla: PT1H` for the endpoint tests. No migration, no new dependency. The M2-2 code and SQL are untouched.

- Acceptance check ("a step past its due time appears in `GET /notify/overdue`; a `TriageService` token gets 403"): covered by the scoping and auth tests and by the lead's Compose run above.

## What each test proves
- `scopingByRole` (7 cases, including a token with no `role` claim, which gets `[]`): Approver sees only steps listing their `sub`; an Approver in no list gets `[]`; a Requester gets `[]` even when listed; Admin sees all four including the unassigned one; Admin+Approver gets the Admin view; out-of-order inserts come back oldest first.
- `unauthenticatedOrTriageServiceIsRefused`: no token and a junk token give 401, `TriageService` gives 403.
- `nonUuidSubjectGetsEmptyListNotAnError`: no 500 on a `sub` that is not a UUID.
- `closedRowsNeverAppear`; `notYetDueAndExactlyDueAreExcludedOneSecondLaterIsIncluded` (injected clock, no sleeps); `orderedByDueAtOldestFirst`.
- `responseMatchesTheOverdueStepContract`: reads `OverdueStep` from `contracts/openapi/notification-service.yaml` (fails, not skips, if the file is missing), asserts the response keys equal the schema's required keys (8), `dueAt = pendingSince + SLA`, millisecond UTC `Z` timestamps, `position` string, `assignedUserIds` array.
- `StepSlaPropertiesTest` (parametrized): `PT1M` and `PT24H` bind; `PT0S`, `-PT1H`, `24`, `24h`, `abc`, `PT24` and empty fail, and the message names `NOTIFY_STEP_SLA` and gives `PT24H` as an example.

## Decisions made
- `dueAt` is computed at query time, so an SLA change applies to every open step. Alternative: store `due_at`, rejected because it freezes old SLAs.
- A step is overdue when now is strictly after `dueAt`; at exactly `dueAt` it is not.
- The scheduled overdue job is deferred to M2-4 (lead's decision), where `overdue_since` and the "pushed" marker belong with the push.
- Admin wins over Approver when a token has both roles. A non-UUID `sub` for an Approver gives `[]`.

## Review this hardest
- `OverdueService.overdueFor`: the role to scope mapping, since it is the access control for this endpoint.
- The `ANY(assigned_user_ids)` query with the `CAST(:assignee AS uuid)` parameter.
- Timestamp format: Jackson writes `Instant` as ISO text and drops trailing zero fractions (e.g. `...:02Z` or `.4Z`); still valid `date-time`.
