## Decisions made
- Network failures: the generated client returns `{error}` with no `response` instead of throwing, so "no response" means unreachable. A throw in the screen can only come from secure storage or navigation, so it shows the generic message.
- Identifier is trimmed; password is sent exactly as typed (tested). Button is disabled while a field is empty or a request is pending; the second press during pending is ignored (tested).
- The demo hint lists four email addresses, only when `__DEV__` is true. No password, no prefill.
- `replace`, not `navigate`, so Back does not return to Login.
- Smoke script: Node type stripping (22.18+ / 23.6+) plus a small resolve hook, because the generated files import without extensions. No `tsx` or other dependency. It sets the base URL itself and calls the API port directly because the proxy does not exist until M5 (header comment says so).
- Tests mock `globalThis.fetch` and restore it after each test. `expo-secure-store` is mocked inside the test file only.
- In this RNTL version `fireEvent` is async and awaiting a press that awaits a never-resolving promise deadlocks, so the pending-state test uses `void fireEvent.press`.

## Review this hardest
- `LoginScreen.signIn`: after success the button stays disabled because the screen is replaced. If storing or navigating throws, the catch clears the token, shows the generic message and `finally` re-enables the button (tested with a throwing `replace`).
- The resolve hook in `smoke-login.mjs` only rewrites relative imports from `src/api/generated/`. If the generator output changes shape the script may need an update; tests do not cover the script.
- The 400 message picks the first field message from `errors`; the key names are ignored on purpose (the contract says so).
