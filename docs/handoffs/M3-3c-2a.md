## What changed (under `triage-copilot/`, not committed)
- `app/consumer.py`:
  - `declare_topology(channel)`: prefetch 2; exchange `servicedesk.events` (topic, durable, no arguments, same as the API) first; fanout `copilot.dlx`; durable `copilot.triage.dlq` bound to it; durable `copilot.triage` with only `x-dead-letter-exchange=copilot.dlx`, bound to `request.submitted` only.
  - `Consumer(deps, connect=, handle=, on_ready=, on_lost=)`: `start()` connects (`robust_connector(settings)` uses `aio_pika.connect_robust`, reconnect interval 5 s, password via `get_secret_value()` only at the call), declares, consumes, registers `close_callbacks`/`reconnect_callbacks`, then awaits `on_ready`. `stop()` sets the stop event, closes channel then connection. `on_ready`/`on_lost` are the stubs 2b fills with the marker file and Redis ping.
  - `on_message`: ACK gives `ack`; RETRY waits `delay_seconds` then `nack(requeue=True)`; DEAD_LETTER gives `reject(requeue=False)`.
  - Backoff is `asyncio.wait_for(stop_event.wait(), delay)`, so `stop()` wakes it and the message is nacked, or redelivered when the channel closes; never lost (with real aio-pika, `stop()` may close the channel before the woken nack runs).
  - An exception escaping `handle()` is a bug (the handler already turns Redis and agent faults into Decisions): `reject(requeue=False)` to the DLQ, class name logged, no `exc_info`, no body. Requeueing would loop a poison message.
  - A failing `ack`/`nack`/`reject` (channel gone) is logged by class name and swallowed; the broker redelivers an unsettled message. `CancelledError` is not caught.
