# Hand-off: M5-1 Reverse proxy, one address for the phone

**Agent:** lead  **Date:** 2026-11-19

## What changed
- `proxy/nginx.conf` (new): `/api/` → `api:8080`, `/notify/` → `notify:8081`, paths passed through unchanged (the contracts already carry both prefixes). `/proxy-health` answers 200 for the Compose health check. Every other path returns 404, so the copilot, the brokers and the databases are not reachable through the proxy. Request bodies capped at 64 KB; 5 s connect and 30 s read timeouts; `X-Forwarded-*` headers set.
- `docker-compose.yml`:
  - **New `proxy` service:** `nginx:1.27-alpine`, published on `${PROXY_PORT:-8000}` on all interfaces so a phone on the same network can reach it. It depends on api and notify being healthy, and has a `wget` health check on `/proxy-health`.
  - **`api` and `notify` ports are now bound to `127.0.0.1` only.** They were on all interfaces. The phone can no longer bypass the proxy (rule 8); local checks still use `localhost:8080` and `localhost:8081`.
- `.env.example`: optional `PROXY_PORT`, and how the phone's base URL is formed from it.
- `mobile/.env.example`: the placeholder now points at the proxy (`http://<LAN IP>:8000`), and the "until M5" note is removed.

## How it was verified
Run with `docker compose up --build`, the stack built from this branch on top of main `8e23c3c`. All eight services were healthy, the proxy included.

Through `http://localhost:8000`:
- `/proxy-health` returns 200.
- `POST /api/auth/login` works.
- `GET /api/service-requests/pending-for-me` returns 200 with a token.
- `GET /notify/health` and `GET /notify/overdue` (with a token) both return 200.
- `/health`, the api's own health endpoint, which isn't under `/api`, returns 404.
- `/copilot/health` returns 404.

Other checks:
- `docker compose ps`: api is on `127.0.0.1:8080`, notify on `127.0.0.1:8081`, and the proxy on `0.0.0.0:8000`.
- **Acceptance check from PLAN.md ("The phone uses a single base URL"): pass.** The mobile app's own `npm run smoke:login` with `API_BASE_URL=http://localhost:8000` signed in as `it.manager`, and a wrong password gave HTTP 401. The app's generated clients already put `/api` and `/notify` under one `EXPO_PUBLIC_API_BASE_URL` (M4-1b).
- The first run reused a stale copilot image built from the unmerged #46 branch; it exited because main's Compose has no broker settings yet. With `--build` everything was healthy. This was not a proxy issue.

## Decisions made
- **nginx** (an official image, pinned to `1.27-alpine`) because it is the most familiar choice and needs a single config file. Alternative considered: Caddy (shorter config), rejected because it is less familiar to reviewers and the automatic TLS isn't needed for a LAN demo.
- **Port 8000 by default**, configurable. It avoids 80, which often needs root or clashes on a dev machine.
- **No path rewriting.** The contracts' paths already start with `/api` and `/notify`.
- **api and notify bound to localhost** rather than unpublished, so the lead's checks and scripts keep working on the host.

## Review this hardest
- The `docker-compose.yml` port changes. Anything that reached `:8080` or `:8081` from another machine now has to use the proxy. Inside Compose, services still use `api:8080` and `notify:8081`.

## Not done / follow-ups
- **No TLS.** The phone uses plain HTTP on the LAN. Needed before M6-4 (a public deployment).
- **Swagger is not routed.** It isn't under `/api`. M6-4 wants a public Swagger link, so add a route then (or move Swagger under `/api`), and keep it to Development or the deployed demo only.
- **Merge note:** #46 also edits `docker-compose.yml`: copilot's `depends_on` and environment, and api's `depends_on`. This PR changes api's and notify's `ports` lines and adds the `proxy` service. The two touch different lines, so a clean merge is expected. The lead will rebase whichever lands second.

## Contract or rule questions
- Rule 8 (the phone talks only to the proxy) is now enforced on the network side too: api and notify are no longer published on all interfaces.
