## Decisions made
- Dependencies pinned in `requirements.txt` (fastapi 0.164.0, uvicorn 0.54.0, httpx 0.28.1, pydantic-settings 2.16.3) and `requirements-dev.txt` (pytest 9.2.0), as approved. No pytest-asyncio or respx: tests use the anyio plugin and `httpx.MockTransport` with a `StubApi` that records calls.
- 401 handling: invalidate, fetch a new token, retry once; a second 401 raises `ServiceAuthError`. A 401 from the token endpoint raises at once with no retry. The error names the client ID and never the secret.
- 403 and other statuses are returned to the caller unchanged (advisory role).
- `pythonpath = .` in `pytest.ini` so tests import `app`.
- No lock around token fetch, as agreed: the M3-3 consumer handles one event at a time. Later option: an `asyncio.Lock` in `get_token` if consumers become concurrent.

## Review this hardest
- `ServiceDeskClient.request`: the retry path (invalidate, resend once, raise on second 401) and that the retry resends the same kwargs (fine for JSON bodies; a streamed body could not be resent).
- Token expiry maths in `get_token`: refresh when `now >= expiresAt - skew`; a naive timestamp is treated as UTC.
