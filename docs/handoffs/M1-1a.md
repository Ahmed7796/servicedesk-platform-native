## Decisions made
- Factory is in Application, not Domain, because JSON is not a domain concern and `approverUserIds` comes from a query. Alternative: domain events on the aggregate (needs I/O inside the domain).
- Blank comment: `ApprovalStep.Decide` trims and stores a blank or whitespace comment as `null`, so the payload's `comment` is `null`, never `""` (the schema has `minLength 1`). The factory reads `Comment` from the decided step and adds no extra rule. A test covers `null`, `"   "` and a padded comment.
- Reject reason is the step's stored `Comment`. If it is null the factory throws, since `Reject` always requires a reason.
- Callers pass the decided step captured BEFORE the transition (`request.CurrentStep`) and the previous status for cancel; the factory reads `CurrentStep` AFTER the transition for `currentStep`/`nextStep`.
- No JSON Schema package. Tests compare the produced JSON with `contracts/events/examples/*.json` (same keys at every level, same JSON kinds, null may swap with string) and check enum values and uuid format against `defs.schema.json`. Alternative: a validator package such as JsonSchema.Net (test-only), not approved.
- The tests find `contracts/events` by walking up from the test output folder. If it is not found, the helper throws an exception that lists every path searched, so the test fails; it never skips.
- `occurredAt` is written from `now.UtcDateTime` so it ends in `Z`.

## Java to C# notes (C# tasks only)
- `static class OutboxEventFactory` is like a Java final class with a private constructor and static methods (a utility class); C# lets you mark the class `static` so it cannot be instantiated.
- `record` types (`SubmittedPayload(...)`) are like Java records: immutable data carriers with generated equals and accessors. The generic `EventEnvelope<TPayload>` is like `Envelope<T>`; unlike Java, generics are kept at run time, so no erasure.
- `System.Text.Json` with `JsonSerializerDefaults.Web` is like Jackson with camelCase naming. Differences that matter: enums are written as names only when the options carry a string-enum converter, and I pass enum values as `.ToString()` strings in the records instead; nulls are written because `DefaultIgnoreCondition = Never` (Jackson's `NON_NULL` is the opposite setting).
- `Guid.CreateVersion7()` is like generating a time-ordered UUID (v7); Java's `UUID.randomUUID()` is v4 and not time-ordered.
- `DateTimeOffset` is like `OffsetDateTime`; `.UtcDateTime` gives a `DateTime` with Kind=Utc, which the serializer writes with a trailing `Z`, like `Instant`.
- `IEntityTypeConfiguration<OutboxMessage>` is like mapping the table in a JPA `@Entity`, but kept in a separate class, not annotations; `HasFilter` is a SQL Server filtered index, which JPA has no annotation for.
- A `Theory` with `MemberData` in xUnit is like a JUnit 5 `@ParameterizedTest` with `@MethodSource`.
- `private OutboxMessage() { }` with a public constructor beside it: EF Core needs a parameterless constructor to build rows from the database, like JPA's required no-arg constructor.
