## Notes for M4-4b (from the coordinator, plus what I checked)
- Reject sends `{ reason }` (required, 1 to 500). Approve sends `{ comment }` (optional, max 500), or `{}` when empty. The brief said "comment" for both; the contract wins.
- 403 message: do not name unchecked reasons. I looked read-only at `servicedesk-api/src/ServiceDesk.Domain/Entities/ServiceRequest.cs`: `FindDecisionBlock` refuses the requester (`IsRequester`), the wrong position (`WrongPosition`) and the wrong department (`WrongDepartment`); `DomainExceptionHandler` maps `ApprovalNotAllowedException` to 403 and `InvalidStateTransitionException` to 409. Self-approval is therefore refused, but the 403 body is either ProblemDetails or empty (role check), so the phone cannot tell the reason. Use a message such as "You can't decide this step. It may be waiting on a different approver." Do not claim a specific reason.
- 409 = status no longer allows it, or a concurrent update won (contract `Conflict`). Message: someone else has acted or the request changed; refetch the detail.
- DECIDED by the lead: Approve/Reject show only when status is `Submitted` or `InReview` and a step with `decision === 'Pending'` exists; the server stays the authority via 403/409. (Earlier analysis follows.) Keeping the error text visible while retrying is accepted.
- Show Approve/Reject only where the contract says deciding is possible. The contract has no explicit "can decide" field. The closest line is the `PendingItem.status` description: "Submitted or InReview." (`contracts/openapi/servicedesk-api.yaml`, schema `PendingItem`). Domain code agrees: `RequestStateMachine.CanFire(Status, ApproveStep)` gates it. Suggested rule: show the buttons when `status` is `Submitted` or `InReview` and a step with `decision === 'Pending'` exists; the server stays the authority (403/409). Confirm this wording with the coordinator.
- Pending list does not refetch on focus; add the `refresh?: number` param to `PendingApprovals` as planned.
